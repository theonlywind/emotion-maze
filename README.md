# 食走壓力，食出好心情

一個俾 6-12 歲小朋友玩嘅嘉年華攤位情緒健康遊戲，沿用 Pac-Man 框架，用 HTML + Canvas 寫，
零依賴、唔使 build、開個檔案就玩得。

迷宮入面四個情緒角色（藍藍／阿嬲／驚驚／擔心蟲）係需要被安撫嘅情緒，唔係「要殺死」嘅敵人。
玩家食正面元氣丸之後就可以行過去安撫佢哋，佢哋會平復返、去情緒屋休息一陣，再出返嚟。
未安撫之前被佢哋掂到會扣能量（每人 3 條，唔回復），能量用晒就出局，全部人出局就 Game Over。

> ⚠️ 呢個係**公眾教育／推廣**用途嘅攤位遊戲，**唔係臨床治療或者評估工具**。

## 點開

**攤位／派俾人用**：直接 double-click `食走壓力，食出好心情.html`（單一檔案，內含全部素材，離線都行到）。

**開發／改嘢**：起個 local server（因為要載 sprite，直接開 `index.html` 會被瀏覽器嘅 file:// 限制擋住）：

```bash
python3 -m http.server 8777
```

改完之後，重新出單一檔案：

```bash
python3 build_single_file.py
```

## 操作

| | |
|---|---|
| 1 號玩家鍵盤 | 方向鍵 或 WASD，Enter／空白鍵 = 確認 |
| 藍牙手掣 | 最多 4 隻，搖桿／十字鍵移動，A 掣確認；遊戲中途插拔都得 |
| 觸控螢幕 | 喺畫面上掃控制 1 號玩家，撳一下 = 確認 |
| 志工設定 | 長按 `Esc` 3 秒，或同時長按兩隻手掣嘅 Select/Back 掣 3 秒 |
| 高分榜入名 | 5 個位，**全程可以淨係用手掣**：上下揀字（撳住會連續轉）、左右換位、A 掣下一格（最後一格再撳 A 落實）、B 掣返上一格、Start 掣直接落實。多人局只認得獎嗰位玩家嘅手掣。有鍵盤都得：打英文字母／數字，Backspace 刪，Enter 落實 |

### 手掣搖桿漂移／自己郁

- 手掣被偵測到嗰陣，會記低搖桿靜止值當 0 點（漂移 ±0.6 以內都校正得到），所以**插手掣嗰一刻唔好撥搖桿**。
- 搖桿要撳到約一半力（0.5）先開始郁，郁緊之後放到 0.35 以下先算放手，唔會喺邊緣一郁一停。
- 仲係自己郁：長按 Esc 3 秒開志工設定，下面會列出瀏覽器見到嘅每隻手掣——邊個 slot、型號、對應方式、各個軸嘅數值同被撳住嘅掣。某個軸或者掣一直有數值（例如「軸」入面有 ±0.8 以上嘅靜止值，或者十字鍵 12-15 一直喺「撳住嘅掣」），就係嗰隻手掣嘅問題，拔咗佢或者換隻。

多人局玩完之後，**只邀請全場最高分嗰一位**入名（畫面會顯示係 P 幾），其他玩家唔使排隊打字。

## 能量（每位玩家獨立）

> **2026-11 玩法改動**：試玩後發現被情緒角色掂到完全冇後果、冇挑戰，所以由原本嘅「安心值（會自己回、唔會輸）」改成有能量（最初叫「命」，之後叫過「元氣」）、有 Game Over。呢個**取消咗** GDD 2.6「唔死亡、唔懲罰」簽署條件，係項目負責人試玩後明確要求嘅改動。

HUD 右邊逐個玩家一格：玩家顏色 + P幾 + 三粒紅心 ♥（玩家頭上都有細心，唔使望返去 HUD）。
被掂到嗰刻會紅邊閃一下 + 輕微震動（單次 0.5 秒；系統設定「減少動態」會關咗震動）。

HUD 其他重點（現場距離望得清）：時間大數字、過關進度條、全隊**分數**、每位玩家自己顏色嘅格（P 編號、個人分數、能量）、**四格「安撫」**——每安撫成功一次就填一格，格內係嗰個角色安撫成功嘅樣（過關條件係安撫次數，所以按次序填格，唔係逐個角色打剔）。
每局開波會出大字提示「食發光正面元氣丸，追住情緒去安撫佢！」9 秒，食咗正面元氣丸之後再出「追住佢哋，安撫佢！」。四個角落嘅正面元氣丸有脈動光環，比普通代幣大三倍。

- 被**未進入安撫模式**嘅情緒角色掂到 → 扣一點能量，**唔會回復**
- 仲有能量：有 2 秒無敵時間（角色閃爍），避免連環被掂；畫面下方會出「小心！仲有 N 點能量」，剩最後一條會出「最後一點能量喇，加油！」
- 扣到零 → 嗰位玩家**出局**：角色變灰、唔再郁、唔再收代幣，其他玩家繼續玩
- **全部玩家出局 = Game Over**：出「Game Over」畫面，之後照原本流程（角色介紹 → 有上榜就入名 → 開始畫面），開始畫面撳確認掣就可以再玩
- 時間到、或者達標（代幣 + 安撫齊四個角色）仍然係原本嘅結束方式
- 手掣斷線唔會扣能量，嗰位玩家變暗、冇能量會跌；Game Over 要所有玩家（包括斷線嗰位）都出局先觸發，斷線玩家仲有能量嘅話，局會玩到時間到

參數喺 `js/data.js` 嘅 `config`：`lives`（每人幾多點能量，預設 3）、`hit_protect_seconds`（被掂之後嘅無敵時間，預設 2 秒）。

> HUD 呢度**特登唔顯示個人分數** — GDD 4.3 唔准局內喺同伴面前逐個比較分數，個人成績留返去全日高分榜。

## 開始畫面

開始畫面有個選單，上下揀、確認掣入去：

| 項目 | 內容 |
|---|---|
| 開始遊戲 | 直接開波 |
| 認識情緒角色 | 四個角色逐個顯示「平時行緊」→「你食咗正面元氣丸之後」→「安撫成功」三個狀態，等小朋友玩之前就明白呢個轉變 |
| 今日高分榜 | 隨時查得到，唔使等輪播 |
| 手掣連接 | 參考 Switch 嘅手掣畫面：四格顯示邊個 slot 接咗邊隻手掣，郁下手掣對應嗰格會著燈，方便志工認邊隻手掣係邊個玩家 |

冇人郁嘅時候會自己輪播（標題 → 高分榜 → 角色介紹，每 15 秒），**輪播中隨便撳一下確認掣就即刻開波**，細路唔使識揀選單。手動揀咗某個版面之後 30 秒冇人郁，會自動返輪播，唔會成日停死喺同一版。

## 開局前嘅角色介紹（每局都會出）

按 ▶ 開始之後、迷宮開場之前，一定會經過一個精簡角色介紹：一句已簽署文案 + 四個角色「平時行緊 ▶ 安撫成功」嘅圖示對照。**6 秒自動開波，任何掣即刻跳過，冇 lock-out**，守返 GDD 6.1.1 對 PRE-INFO 嘅限制（只得一句字、靠圖唔靠字、唔可以拖住排隊）。想睇詳細版（三個狀態 + 每個角色嘅安撫文案）就喺開始畫面揀「認識情緒角色」。

## 迷宮 v2

由原本 **16×18 直度**改成 **28×17 橫向**（比例 1.65），貼返手提電腦／外接顯示器嘅畫面比例，玩區大過原本一倍以上，唔會再兩邊嘥晒位。

- 232 格可行走，已用 flood fill 驗證全部連通
- **冇死路**：每個路口都有第二條路，小朋友唔會被逼入掘頭巷（呼應追捕唔可以造成驚嚇嘅條件）
- 274 個代幣（每粒 1 分，安撫一次 5 分）、4 個正面元氣丸（四角）、中央情緒屋、中間橫行係傳送隧道
- 過關門檻 `completion_token_percent` 由 0.4 調做 0.3（單人 68 個），因為迷宮大咗，跑同樣時間收到嘅代幣比例會低啲
- **玩家同情緒角色嘅速度冇改**（仍然係玩家 5.625 格/秒、四個角色 0.85/1.1/0.95/0.9 倍），保留 game-director 釘死咗嘅追捕速度校準；迷宮變大令追逐更有走位空間，唔係靠加速

改迷宮淨係改 `js/data.js` 嘅 `level.grid`（同 `grid_width` / `grid_height` / `tunnel_row` / spawn 座標）。改完之後 `css/style.css` 嘅 `#frame` 闊度公式要跟住更新比例（`(96vh - 92px) * 闊/高`）。

## 高分榜點樣儲存（斷線都得）

高分榜同志工設定都係存喺瀏覽器嘅 `localStorage`，**完全唔使上網**：斷網、閂咗瀏覽器再開、甚至重開機，當日嘅高分榜都仲喺度。日期用部機嘅本地時區計，過咗本地時間凌晨 12 點先自動清空。

要留意：
- 記錄係**跟住部機同個瀏覽器**：兩部手提電腦各有各嘅高分榜；轉咗瀏覽器（例如 Chrome 轉 Edge）會見唔到之前嘅記錄
- **唔好用無痕／私隱模式**開，閂咗視窗記錄就冇
- 清除瀏覽器資料會連高分榜一齊清走

志工設定入面可以改遊玩時長（60/90/120/180 秒）、人數上限、開全螢幕、重置今日高分榜。人數上限由**下一局**開始生效：插咗幾多隻手掣都好，只有頭 N 隻（N = 上限）會入局，多出嚟嗰幾隻喺「手掣連接」畫面會變灰。設定會記喺瀏覽器度，落次開機仲喺度。

## 情緒健康設計條件（實作對應位置）

呢啲唔係普通功能，係 GDD 入面 game-director + child-mh-consultant 雙簽署嘅硬性條件（其中「唔死亡、唔懲罰」一條已經取消，見表內）：

| 條件 | 實作 |
|---|---|
| 被安撫唔用吞食／暴力視覺，改用溫暖光圈 | `render.js` `drawCharacter()` 嘅 CAUGHT 分支 |
| 玩家最大張口幀唔可以喺情緒角色附近出現（GDD 9.1.4a CRITICAL） | `main.js` `updateChompRule()` + `engine.js` `Player.sprite()` |
| ~~玩家被捉到唔死亡、唔扣能量、唔講 Game Over~~ **（2026-11 已取消，改成有能量有 Game Over，見上面「能量」）** | `engine.js` `Player.hit()` + `main.js` `Game.update()` |
| 情緒角色會 respawn（「情緒唔會消失，會休息一陣再返嚟」） | `EmotionCharacter` 狀態機 CAUGHT → RESTING → CHASE |
| 追捕全程唔突然加速（唔用 jump-scare） | `EmotionCharacter.currentSpeed()`，SCATTER/CHASE/RESTING 同一個速度 |
| 單局結束唔喺同伴面前逐個比較分數（GDD 4.3） | `ui.js` `setEndMessage()`：多人局只顯示團隊合計 |
| 未打入 Top 10 唔提任何負面訊息 | `main.js` `enterHighscore()` 直接返 attract |
| PRE-INFO 一句、6 秒、可即時跳過；POST-INFO 四句、12 秒、2 秒後可跳過 | `main.js` 流程常數，依 GDD 6.1.1 |
| 音效一律柔和低音量，唔用刺耳警號 | `engine.js` `Sfx`（WebAudio 即時合成，唔使外部音檔） |

## 同 Godot 版嘅差異

- 音效：Godot 版留低咗 placeholder 等人揀 CC0 音檔；HTML 版改用 WebAudio 即時合成柔和音效，即開即有聲。
- PRE-INFO 文案：Godot 版暫時用 `info_panel_zh[0]` 頂住；HTML 版跟返 GDD 6.1.1 指定嘅 `info_panel_zh[1]`。
- 玩家最大張口幀規則：Godot 版標記為未實作；HTML 版已實作。
- 結束畫面個人分數：Godot 版逐個玩家列出；HTML 版多人局改為團隊合計（見上表）。
- 志工設定：多咗全螢幕切換，同埋設定會記喺瀏覽器。
- 高分榜入名：由經典街機 3 個字母（AAA）改為 5 個位，接受英文字母同數字，可以直接用鍵盤打。
